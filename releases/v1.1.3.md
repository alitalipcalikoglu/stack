# atc-web production suite 1.1.3

Release date: 2026-10-06

This immutable security patch release supersedes `v1.1.2` as the supported default installation.
It closes three confirmed credential-handling defects and updates two dependencies with published
advisories. The Console SvelteKit architecture, operation count, generated client operation set,
and MCP exposure are unchanged.

## Version identities

- Stack and the 13 application repositories: `v1.1.3`.
- Shared `service-core`: `v1.12.1` (Fastify peer and development pin `5.12.5`).
- Historical `v1.0.0`, `v1.1.0`, `v1.1.1`, and `v1.1.2` suite tags and the `v1.11.1` and `v1.12.0`
  `service-core` tags remain immutable and unchanged.

The authoritative installer descriptor is
[`../installation-manifests/v1.1.3.json`](../installation-manifests/v1.1.3.json). It binds every
managed official repository to an immutable annotated tag and peeled commit. The default release
is selected by
[`../installation-manifests/supported.json`](../installation-manifests/supported.json).

## Security scope

- **Auth:** `DELETE /v1/users/{id}/sessions` and `DELETE /v1/users/{id}/sessions/{sid}` now require
  an API key with the `write` role. Previously a `read`-only key could end any user's sessions. Keys
  without an explicit role keep their `readwrite` default, so Stack-issued keys are unaffected. The
  canonical OpenAPI documents the new `403 FORBIDDEN` response; operation identities are unchanged.
- **Media:** the `media.upload.ticket` audit event now carries the ticket's SHA-256 hash, the same
  value the ticket is stored under, instead of the plaintext single-use upload token.
- **Scheduler:** the `scheduler.job.update` audit meta keeps only the target `url`, `method`, and
  header names. Header values and the target body can hold credentials and are no longer forwarded.
- **Webhook-out:** the `webhook.subscription.update` audit meta reduces custom `headers` to their
  names.

## Dependency scope

- **Fastify `5.12.5`** in every Fastify-based service and in `service-core`
  ([GHSA-4mh8-r7rc-xpvc](https://github.com/advisories/GHSA-4mh8-r7rc-xpvc), moderate). No service
  enables HTTP/2, so the advisory was not reachable; the upgrade keeps the production audit at zero.
- **Console `devalue` `5.9.4`** (high, multiple advisories) through SvelteKit's existing range.
  `devalue` serializes SSR load data, so it ships in the adapter-node output.
- Console now declares `fastify` as an exact-pinned development dependency and `types: ["node"]` in
  `jsconfig.json`. These only keep `service-core`'s JSDoc types resolvable for typechecking. Console
  neither imports nor runs Fastify.
- Console's runtime identity oracle reads the installed `service-core` version from package metadata
  instead of a frozen literal.

## Not changed

- Auth `GET /v1/users` remains available to any valid key, as documented.
- The verification-resend `409 ALREADY_VERIFIED` signal remains. Removing it alone does not close
  enumeration, because the resend throttle exposes the same signal; that needs a separate decision.
- The three accepted low-severity development `cookie` advisories remain.
