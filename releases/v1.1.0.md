# atc-web production suite 1.1.0

Release date: 2026-09-20

This immutable suite release closes the production hardening, API contract, typed-client, Console
API documentation, and distribution plan. It includes canonical OpenAPI 3.1 documents and runtime
`GET /openapi.yaml` serving for all 13 HTTP services, locally bundled read-only Console API Docs,
376-operation generated TypeScript clients, `stack install:all`, and the supported 10-tool MCP
foundation.

## Version identities

- Suite, stack, and 13 application repositories: `v1.1.0`.
- Shared `service-core`: `v1.12.0`. The minor bump reflects the backward-compatible public
  `registerOpenApi` export introduced after immutable `v1.11.1`.
- Application lockfiles resolve `service-core` to the exact `v1.12.0` commit.
- The original `v1.0.0` application/stack tags and the `service-core` `v1.11.1` tag remain
  immutable and unchanged.

The authoritative installer descriptor is
[`../installation-manifests/v1.1.0.json`](../installation-manifests/v1.1.0.json). It binds every
managed official repository to both an annotated tag and its peeled commit. The default release is
selected by [`../installation-manifests/supported.json`](../installation-manifests/supported.json);
the archived `v1.0.0` descriptor is retained byte-for-byte.

## Validation evidence

- Production dependency trees were valid and production audits reported zero vulnerabilities in
  all 15 repositories and the isolated MCP package.
- Every changed application completed `npm ci`, its full tests, and typecheck; Console also
  completed its production build. `service-core` completed 98/98 tests and typecheck.
- Stack completed 90/90 tests with `STACK_INTEGRATION=1` and no skips. Canonical contract checks
  passed for 13/13 services, including exact route parity, info parity, and global `operationId`
  uniqueness.
- Typed clients cover 376 operations, regenerate deterministically, pass drift/type/test checks,
  and completed 3/3 real service-backed smoke tests.
- The reconciled MCP catalog covers 376 operations. The explicit allowlist remains exactly 10
  tools; unit tests passed 17/17 and real STDIO E2E passed 14/14.
- Production Docker images for a shared-core consumer (`notify`), `gateway`, and `console` built
  successfully and ran as the non-root `node` user. `/health`, `/ready`, `/v1/info`, and
  `/openapi.yaml` returned 200 for all three in the smoke harness.
- A disposable release install cloned the 14 official managed repositories, verified every remote
  tag and commit, ran every lockfile install, ran setup, built Console, and left 13/13 canonical
  specs present. A rerun reused all 14 repositories with unchanged commits, clean Git trees, and
  unchanged generated secrets/configuration hashes.
- From that fresh install, a real Console session listed all 13 documentation services and fetched
  `notify`'s canonical OpenAPI 3.1.0 document through the authenticated Docs backend.
- Development `install:all --ref main --dry-run --no-start` resolved all 14 official moving heads
  without writing to its disposable workspace.

PM2 was not installed in the release-validation environment, so the default PM2-managed 13/13
started-install E2E was not claimed. This is an environmental limitation, not a release blocker:
the full production-process integration suite, three real production-image smokes, and the fresh
release Console/notify process smoke all passed.

## MCP product boundary

MCP expansion was intentionally cancelled. Supported scope is STDIO only, with the explicit
10-tool allowlist, no destructive/admin tools, no remote transport, no MCP-specific authentication,
and no package publication. This is a product decision rather than pending release work.

## Known deferred items

- Some operational `operationId` naming remains historically inconsistent.
- Historical dead error codes remain documented where source audits identified them.
- Specialized internal clients remain intentionally separate from the generated public clients.
- Console's Swagger UI bundle is large and emits a build-time chunk-size advisory; it is locally
  bundled, has no CDN or telemetry, receives no service API keys, and keeps request execution and
  authorization persistence disabled.

Exact immutable tag/commit identities and final test counts are recorded in `v1.1.0.json` on
`main` immediately after the stack tag is cut, because a commit cannot contain its own Git object
ID. No GitHub Release object or GitHub Actions workflow is part of this release policy.
