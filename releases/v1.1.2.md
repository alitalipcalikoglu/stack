# atc-web production suite 1.1.2

Release date: 2026-09-22

This immutable corrective patch release supersedes `v1.1.1` as the supported default installation.
It preserves the completed Console SvelteKit architecture and all public contracts while correcting
release-version test oracles that were discovered during final verification of the immutable
`v1.1.1` artifacts. No public API, operation count, runtime behavior, dependency version, generated
client surface, or MCP exposure changes in this patch.

## Version identities

- Stack and the 13 application repositories: `v1.1.2`.
- Shared `service-core`: unchanged at its independent `v1.12.0` release.
- Historical `v1.0.0`, `v1.1.0`, and `v1.1.1` suite tags and both `service-core` release tags remain
  immutable and unchanged.

The authoritative installer descriptor is
[`../installation-manifests/v1.1.2.json`](../installation-manifests/v1.1.2.json). It binds every
managed official repository to an immutable annotated tag and peeled commit. The default release
is selected by
[`../installation-manifests/supported.json`](../installation-manifests/supported.json).

## Corrective scope

- Console and Gateway current-version assertions now compare runtime identity with package metadata
  read through an independent test path instead of frozen suite-version literals.
- Flags, Media, Ratelimit, and Shortlink received the same preventative independent-oracle pattern.
- All 13 application package identities and Stack use `1.1.2`; lockfile root metadata matches.
- Console remains one adapter-node SvelteKit application with filesystem routing and `server.mjs`
  as its canonical production entrypoint. No Fastify application, legacy UI SPA, custom application
  router, SPA fallback, or legacy runtime was restored.

## v1.1.1 historical status

`v1.1.1` remains exactly as published. Its default installer resolution, exact-SHA installation,
canonical Console architecture, and 13/13 runtime readiness succeeded. Final verification then
found stale version expectations in the tagged Console and Gateway test suites, so `v1.1.1` is not
described as fully verified or production-ready. No tag, manifest, or historical source was moved or
rewritten; `v1.1.2` is the immutable correction.

## Pre-publication validation

- Every version-bumped repository completed its full test suite after package metadata became
  `1.1.2`; Console passed 131/131, Gateway 52/52, and Stack passed 92/92 with integration enabled and
  zero skips.
- Console typecheck completed with zero errors and warnings. Filesystem API parity remained 156/156,
  frontend parity 34/34, and the suite remained 13 specs / 376 operations.
- Generated TypeScript clients remained 13/13 and 376/376 with no drift and 6/6 tests. MCP remained
  a 376-operation catalog with an explicit 10-tool allowlist and 17/17 tests.
- Production dependency audits reported zero vulnerabilities. The accepted three low-severity
  development advisories remain unchanged.
- An official-origin `install:all --ref main` candidate run cloned 14/14 exact manifest commits,
  completed deterministic installs and setup, built Console, reached 13/13 readiness, passed
  integration, PM2, Docker, host-port, browser, and security gates, and safely reused 14/14 repos.

Exact immutable tag identities and authoritative post-publication default-install evidence are
recorded in `v1.1.2.json` on `main` only after that verification succeeds. No GitHub Release object
or GitHub Actions workflow is part of this release policy.
